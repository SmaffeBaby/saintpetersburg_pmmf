# Петербургский международный молодежный форум

Nuxt 4, Vue 3, Nuxt UI 4, Tailwind CSS 4, Pinia, SQLite и Redis. Supabase не используется.

## Локальная разработка

Нужен **Node.js 24 LTS** (`nvm use`).

```sh
cp .env.example .env
npm ci
npm run dev
```

В `.env` задайте `ADMIN_PASSWORD` и отдельный случайный `ADMIN_SESSION_SECRET` (например, `openssl rand -hex 32`). Остальные SMTP-параметры нужны для писем: при сбое отправки заявка всё равно сохраняется в SQLite.

`http://localhost:3001/admin` — вход по паролю, заявки с фильтрами и Excel-экспортом, редакторы шести разделов сайта. В каждом редакторе доступны русский и английский тексты, ссылки и существующие настройки компонента. Изменения публикуются кнопкой «Сохранить» без сборки и перезапуска. Это редактор данных компонентов, а не редактор Vue-кода или произвольного CSS. В форме регистрации нельзя удалить или переименовать обязательные поля; можно менять подписи, подсказки и ширину. При одновременном редактировании устаревшая версия не перезапишет новую.

## Данные и кеш

- SQLite: `data/saint-mmf.sqlite`, путь меняется через `DATABASE_PATH` / `NUXT_DATABASE_PATH`. Режим WAL и транзакции; таблицы создаются автоматически при первом обращении.
- При первом открытии базы `registrations.json` **в каталоге базы** импортируется целиком в одной транзакции с исходными ID и датами. Исходник сохраняется; повторного импорта и восстановления удалённых заявок не происходит. Некорректный файл останавливает импорт без частичного переноса: исправьте его и повторите запуск. Переносите JSON до первого обращения к новой базе.
- Начальные настройки сайта взяты из прежних YAML в `shared/config/content-defaults.json`. После первого обращения настройки живут в SQLite; YAML остаются историческими исходниками и больше не читаются сайтом.
- Redis кеширует только публичный контент на 5 минут. Номер ревизии и дата обновления входят в ключ, поэтому сохранённые изменения видны сразу. Заявки и персональные данные в Redis не копируются. Без `REDIS_URL` или при недоступности Redis контент читается из SQLite; временные ключи сами удаляются.
- База должна находиться на локальном постоянном диске. Для нескольких серверов с разными дисками нужен переход на общую серверную СУБД. Для резервной копии используйте SQLite backup API/CLI (`.backup`) либо остановите приложение перед копированием всего каталога `data` (включая WAL/SHM). Не копируйте только основной файл работающей базы.

## Docker

```sh
docker compose up -d --build
```

Приложение доступно на порту 3001. Compose поднимает приватный Redis без внешнего порта; постоянная SQLite находится в смонтированном `./data`. Redis хранит только восстанавливаемый кеш и ограничен 64 МБ. Значения `.env` передаются через runtime config; файл с секретами в образ не попадает.

## Проверки

```sh
npm test
npm run typecheck
npm run build
npm run test:integration
```

Тесты используют временные базы и проверяют перенос JSON, повторный запуск после удаления, откат некорректного импорта, сохранность данных между подключениями, контроль ревизий и валидацию настроек.
